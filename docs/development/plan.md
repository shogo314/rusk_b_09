# 作業計画

## 目的と開始点

β09は、既存の言語仕様を保ちながらコードを整形できるフォーマッタから始めます。以降の言語拡張は、必要性と設計を確認してから範囲を決めます。

開始点は[β08完成版](https://github.com/shogo314/rusk_b_08/commit/2527b35b836099567fbcb74903cd5fbb673707f8)です。処理系・標準ライブラリ・テストを引き継ぎます。現在のCLIにはまだ整形コマンドはありません。

## 最初に進めること

| 順序 | 仕事 | 確認すること |
|---|---|---|
| 1 | 現在の文法・CST・トークン位置を調べ、コメントと空白の保持方法を決める | コメント、文字列、externのC++本文を失わずに読み戻せること |
| 2 | 整形規則と小さな試作を作る | インデント、改行、演算子・型引数・ブロックの配置を代表例で確認すること |
| 3 | 現在使える構文全体に対応する | 括弧・ブロック末尾の`;`など、意味に影響する記号を保つこと |
| 4 | clapのCLIに組み込む | 標準出力、整形済みかの確認、ファイル更新の操作と終了コードを決めること |
| 5 | テスト・examples・文書で確認する | 再整形しても変化せず、実行結果と診断の意味を保つこと |

最初は構文に基づく整形に集中し、型検査や最適化を整形の前提にしません。文字列・文字リテラル・extern本文は内容を変更しません。コメントの内容と対応する位置関係を保持します。整形のための新しい言語構文は追加しません。

CLIの候補は`rusk fmt FILE`、`--check`、`--write`です。既定の出力先、複数ファイルへの対応、改行や空行の細則は、試作を確認して決めます。この記法は実装済みの操作ではありません。

## フォーマッタの完成条件

- 現在の文法を網羅し、未対応の構文を黙って削除・変形しない。
- 整形結果を再び構文解析でき、再整形した結果が一致する。
- 位置情報を除いた構文の一致と、実行例による意味の一致を確認する。
- コメント、リテラル、C++本文、演算子の結合、ブロックの値を保つ。
- 不正な入力では診断を出し、ファイルを更新する場合も元の内容を壊さない。
- CLI、掲載例、既存のテストとCIを確認し、整形規則と使い方を文書に載せる。

## その後の候補

ジェネリック型に制約を付け、その契約に基づいて定義時の解析を行う仕組みを検討します。制約の表記、操作の解決、外部の型への適用、効果・共有の契約、既存の具体化との互換性を整理してから採否を決めます。トレイトや特定の構文の採用は、まだ決めていません。

数値型や内側の名前付き関数など、ほかの未実装項目は[将来の方針](../future.md)を参照してください。ここにある候補すべてをβ09の完成条件には含めません。
